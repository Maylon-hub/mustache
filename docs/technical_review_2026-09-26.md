# Technical and functional review — 2026-09-26

This review prioritizes scientific consistency, historical functionality and
reproducibility over speed. HAI remains the primary hierarchy agreement measure.
No clustering validation score or tree edit distance replaces it.

Follow-up clarification (2026-09-27): this historical review used "compact"
too broadly for the legacy representation. The inspected Java launcher passes
`compact=False`; the confirmed distinction is its interval/terminal-leaf
representation, including zero distance within a terminal leaf. Full Java-output
equivalence remains untested. CORE-SG is the principal engine; the separate
HDBSCAN engine is an auxiliary comparison baseline. Internal HDBSCAN routines
remain part of tree processing and automatic meta-clustering.

## Scientific definitions and interpretation

HAI is `1 - 2/n² * Σ(i<j) |d_H1(i,j) - d_H2(i,j)|`, with normalized LCA
cluster cardinality for the represented hierarchy. Exact evaluates all distinct
pairs; approximation uses shared uniform distinct pairs with replacement,
PCG64 and a recorded seed/budget. The Hoeffding bound is per comparison, not a
simultaneous guarantee for the whole matrix or a stable meta-partition.

A medoid represents a hierarchy, not a dataset point. It minimizes the sum of
`1 - HAI` within its meta-cluster. The user's interpretation of this criterion,
and the distinction between HAI and ARI/AMI/DBCV, is correct. Ties choose the
first hierarchy in sorted `ordered_mpts`; automatic noise is not a medoid.

The interpretation requiring correction is that an independently generated
OPTICS plot necessarily visualizes the selected HDBSCAN/CORE-SG hierarchy.
It does not. These are different constructions even with the same mpts. The
corrected geometry is explicitly hierarchy-derived, not described as OPTICS.

The historical angular/Pearson/supremum names also cannot be assumed portable
across modern backends. Both supported algorithms are tested end-to-end with
Euclidean, Manhattan, Chebyshev, Minkowski p=2 and Cosine. Zero vectors are
invalid for Cosine; arbitrary Minkowski p and old aliases are not exposed.
The optional Euclidean t-SNE map is only visualization, with seed 42; it does
not change clustering, HAI or representative geometry.

## Complete flow reviewed

Batch form → validated CSV/numeric data and algorithm/metric/range → one support
fit for CORE-SG or individual native HDBSCAN fits → actual fitted trees → HAI
with aligned `ordered_mpts` → meta labels/dendrogram/medoids → API parameter
payload → all coordinated frontend views. Cut requests update the server
partition and persist it; saving waits for the latest queued threshold.

Storage schema 2 retains original metadata aliases and result keys. It adds
dataset identity, sample count, runtime provenance, source/dataset hashes,
execution time, active and automatic partitions, cut mode/threshold and manual
selection. Reopening restores backend state and frontend views without fitting
again. Older OPTICS layouts are not silently reinterpreted or recomputed.

## Remaining differences and publication limits

1. **Hierarchy representation:** legacy compact terminal leaves give pair
   distance zero. Modern full single-linkage trees retain finer structure.
   Preserving the HAI formula does not prove numerical identity to compact
   Java-generated HAI. The original Java pipeline was not rerun. A faithful
   compact-hierarchy adapter and comparison fixtures remain scientific work.
2. **Meta-clustering:** modern scikit-learn HDBSCAN uses minimum cluster size 2
   and allows one cluster. Original HDBSCAN/FOSC settings differ; the default
   partition is not promised identical. Threshold/manual exploration remains.
3. **Reachability:** adjacent cophenetic heights preserve hierarchy-contour
   intent, but full-tree leaf ordering and the undefined first value differ
   from original compact intervals and artificial first-bar ceiling.
4. **Performance:** correctness restored a real dense distance matrix in the
   CORE-SG fast path. This is quadratic memory and adds distance computation;
   no speedup is claimed for this correction. Old benchmark scripts compared
   unequal workloads and simulated reuse beyond the web request's cache scope.
5. **Deployment:** global in-memory session state is a single-user local tool,
   not isolated multi-user production hosting. CDN assets require connectivity.
6. **Version provenance:** tests use selected source via PYTHONPATH with an
   existing Python environment; installed distribution metadata can differ
   from source candidate versions. This is not a clean-wheel installation test
   or proof of cross-platform release/publication.

## Recommended future work

Prioritize independent Java/compact-hierarchy equivalence fixtures and explicit
configurable FOSC/meta-cluster parameters. Then benchmark equivalent full
workloads (fitting, extraction, labeling, HAI and rendering) with correctness
oracles, multiple seeds/runs and identified artifacts. Evaluate sparse/lazy
exact distance storage without placeholder semantics, approximate HAI stability
and simultaneous confidence bounds, arbitrary Minkowski p, richer manual
representative workflows and isolated multi-user sessions.

DBCV can be added as flat-clustering validation, never as an HAI replacement.
TED variants would require their own representation/cost interpretation and
validation; they are not part of the delivered metric. Publication readiness
must not be claimed until the remaining scientific differences are described
in the manuscript and the target artifacts are independently reproduced.
